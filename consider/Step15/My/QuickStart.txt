## T058 — Project Referenceها، بسته‌ها و مرزها

- Project Referenceهای همهٔ فایل‌های `.csproj` را با plan.md و اصل II در Constitution تطبیق بده:
  Application → Domain؛ DataAccess → Application و Domain؛ Api → Application و DataAccess؛ Tests → Domain، Application و Api.
- بسته‌ها فقط همان‌هایی باشند که T003 و پروژهٔ آزمون لازم دارند؛ هیچ بستهٔ AI، MCP، RAG، Qdrant یا Swagger/OpenAPI وجود نداشته باشد.
- بررسی کن Domain و Application به EF Core، ASP.NET Core یا HTTP وابسته نیستند و `DbContext`/`IQueryable` به Core نشت نکرده است.
- بررسی کن Business Logic در Endpointها یا DataAccess تکرار نشده است.
- مسیرها، HTTP Methodها، status codeها، `ProblemDetails.code`ها، `ETag`/`If-Match` و مدل‌های پاسخ (`AuthorPostSummary`، `AuthorPostDetail`، `EditorPostSummary`، `EditorPostDetail`، `EditorPostHistory`، `PublicPostSummary`، `PublicPostDetail`) را با `contracts/http-api.md` تطبیق بده.
- OpenAPI ایجاد نکن؛ تطبیق قرارداد فقط با بررسی کد و رفتار واقعی انجام شود.
- اگر اختلافی پیدا شد، ابتدا مشخص کن کدام منبع معتبر است. اختلاف ناشی از Implementation را گزارش کن و فقط در صورتی اصلاح کن که رفتار جدیدی ایجاد نکند؛ اختلاف ناشی از Artifact را بدون تأیید من اصلاح نکن (به‌جز `InvalidStatus` که تأیید شده است).

## T060 — اجرای کامل quickstart.md

همهٔ دستورها را از ریشهٔ Repository و روی یک فایل SQLite تازه اجرا کن. پیش از اجرای هر دستور ترمینال از من اجازه بگیر.

1. `dotnet --version` (بررسی .NET 10 SDK).
2. `dotnet restore BlogSpecLab.slnx`.
3. `dotnet build BlogSpecLab.slnx`.
4. `dotnet test BlogSpecLab.slnx` و ثبت تعداد Passed / Failed / Skipped.
5. `dotnet ef --version`: در Repository فایل `.config/dotnet-tools.json` وجود ندارد. اگر ابزار سراسری `dotnet-ef` نصب نیست، آن را نصب نکن و Tool Manifest نساز؛ متوقف شو و گزارش بده.
6. `dotnet ef database update` با همان دستور quickstart.md؛ Migrationهای `InitialIdentity` و `AddPosts` فقط روی پایگاه دادهٔ محلی توسعه اعمال شوند. مسیر واقعی فایل SQLite ایجادشده را ثبت کن.
7. ساخت چهار کاربر نمونهٔ quickstart.md با `provision-user` و بررسی `issue-token`. Tokenها را فقط در همان نشست استفاده کن و در هیچ فایل، Commit، گزارش یا Log ثبت نکن.
8. `dotnet run --project src/03.Endpoints/Api` و اجرای واقعی مسیر اصلی با درخواست HTTP:
   - Author: Create → Edit → Submit
   - Editor: Return با دلیل → Author: Edit → Submit دوباره → Editor دیگر: Approve → Publish
   - Public: مشاهدهٔ پست منتشرشده در `GET /api/posts` و `GET /api/posts/{id}`
   - دریافت `ETag` و استفاده از `If-Match` در هر فرمان
9. حداقل این شکست‌ها را واقعاً اجرا کن و status و `ProblemDetails.code` را ثبت کن:
   - بدون Token یا با Token نادرست → 401 `Unauthenticated`
   - تأیید پست خود توسط ویراستار ۱ → 403 `SelfApprovalNotAllowed`
   - `If-Match` قدیمی → 412 `StaleVersion` همراه `currentStatus` و `currentVersion`
   - ویرایش پست `Published` بدون تأیید پیامد → 409 `ConfirmationRequired`
   - حذف پست `Published` → 409 `InvalidStatusTransition`
   - دسترسی نویسندهٔ ب به پست نویسندهٔ الف → 404؛ پست منتشرنشده در مسیر عمومی → 404
10. سناریوهای ۱، ۴ و ۵ را با HTTP اجرا کن؛ اما سنجش زمان SC-004 (کمتر از ۵ دقیقه) و SC-005 (کمتر از ۱ دقیقه) فقط توسط انسان قابل انجام است:
    - نتیجهٔ زمانی، تعداد شرکت‌کننده یا درصد موفقیت جعل نکن.
    - معیارهای Spec را تغییر نده؛ حداقل ۵ Author و ۵ Editor یا آستانهٔ ۹۰٪ را اضافه نکن.
    - `acceptance.md` ایجاد نکن.
    - اگر من زمان‌سنجی را واقعاً انجام و نتیجه را اعلام نکرده‌ام، T060 باید `[ ]` بماند و بخش خودکار آن در `validation.md` با وضعیت «سنجش انسانی هنوز انجام نشده» ثبت شود.

## T061 — اصلاح quickstart.md

فقط براساس نتایج واقعی T060 اصلاح کن:

- یادداشت ابتدای فایل («هنوز Solution و پروژه‌ها ساخته نشده‌اند») را حذف یا با وضعیت واقعی جایگزین کن.
- سناریوی ۱۶ را اصلاح کن: تصمیم دوم فقط وقتی 412 با `StaleVersion` می‌گیرد که تصمیم اول `Approve` باشد؛ پس از `Return` پست برای ویراستار دیده نمی‌شود (R-13) و پاسخ 404 است.
- هر دستور، مسیر فایل یا خروجی که با اجرای واقعی تفاوت دارد اصلاح شود.
- مفاهیم خارج از Artifactها (`allowedActions`، `PostView`، `PublicPostView`، Request Changes، کدهای snake_case، `503`، دستور Revoke یا `tool restore`) وارد نشوند؛ لغو دسترسی همان حذف Token یا نقش از پایگاه داده است (سناریوهای ۲۲ و ۲۳).
- هیچ Token یا Credential واقعی در فایل ثبت نشود.
- ساختار فعلی سند و قالب `<div dir="rtl">` با بلوک‌های کد خارج از آن حفظ شود.

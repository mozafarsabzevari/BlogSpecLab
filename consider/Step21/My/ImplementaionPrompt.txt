## Taskهایی که در این مرحله عمداً اجرا و تکمیل نمی‌شوند

Taskهایی از `tasks.md` که به یکی از موارد زیر وابسته‌اند را انجام‌شده علامت نزن:

- اجرای واقعی Suite آزمون‌ها و ثبت Pass/Fail
- فراخوانی واقعی Provider xAI (Smoke test)
- اجرای Quality Evaluation با Model واقعی
- Human Evaluation
- ثبت شواهد نهایی Validation و Acceptance

پیش از شروع، فهرست دقیق شناسهٔ این Taskها را از `tasks.md` همین پروژه استخراج و همراه نگاشت نمایش بده.

علت:

این Taskها به اجرای واقعی تست، Provider، Quality Evaluation، Human Evaluation یا ثبت شواهد نهایی Acceptance وابسته‌اند و قرار است در مرحلهٔ بعد به‌صورت آموزشی اجرا شوند.

فایل‌ها و زیرساخت لازم برای اجرای آن‌ها را اکنون آماده کن، اما نتیجهٔ ساختگی ثبت نکن.

آستانه‌های Eval در research.md (R-12) هنوز پیشنهادی هستند؛ آن‌ها را در کد به‌عنوان مقدار قابل تنظیم قرار بده و تأییدشده معرفی نکن.

## دربارهٔ تست‌ها

Taskهایی که می‌گویند Test Code ایجاد شود باید اکنون پیاده‌سازی شوند.

صرفاً به این دلیل که اجرای تست به جلسهٔ بعد موکول شده، نوشتن Test Code را حذف نکن.

بنابراین تست‌های مربوط به:

- Domain (قواعد سازگاری `ContentReview`)
- Application
- Validator
- Transport (Transport جعلی HTTP برای `Infra.AI`)
- Protocol
- HTTP
- needs_input
- Non-Mutation
- Concurrency
- Timeout
- Privacy
- Configuration
- Persistence و دسترسی فقط نویسنده (FR-013)
- برابری Schema جاسازی‌شده با `contracts/model-output.schema.json`
- Provider opt-in
- Quality Eval

باید اکنون وجود داشته باشند.

آزمون‌های Provider و Eval فقط با متغیر محیطی `BLOGSPECLAB_PROVIDER_TESTS=1` اجرا شوند و در اجرای عادی Skip شوند.

ولی اجرای Suite و ثبت Pass/Fail نهایی جزو این مرحله نیست.

## Build

در صورت نیاز برای رفع خطاهای compilation یا dependency می‌توانی `restore` و `build` اجرا کنی، به شرط گرفتن اجازه پیش از هر دستور.

این کار فقط Development Check محسوب می‌شود.

اجرای build را جایگزین Validation، Test یا Acceptance معرفی نکن و به‌دلیل اجرای build، Task مربوط به Validation را تکمیل‌شده علامت نزن.

## xAI

طراحی تأییدشده را رعایت کن:

- Provider: xAI با Endpoint `https://api.x.ai/v1`
- Responses API
- مدل اولیه `grok-4.7`
- package رسمی `OpenAI 2.14.0` با Endpoint سفارشی روی xAI
- نام Typeها و متدهای SDK فقط طبق research.md (R-02) و همان نسخهٔ Package؛ امضای سازندهٔ `ResponsesClient` را با Package نصب‌شده بررسی کن و حدس نزن
- non-streaming
- `store=false`
- Retry خودکار SDK خاموش
- سقف `MaxOutputTokenCount` برابر ۸۰۰۰
- بدون Tool Calling
- بدون MCP
- بدون Web Search، X Search، File Search یا Code Execution
- بدون RAG
- بدون Agent
- بدون fallback خودکار

Structured Output باید با Schema نسخه‌دار `content_review_v1` و `text.format` از نوع `json_schema` با `strict: true` انجام شود.

Artifact موجود:

`specs/002-ai-content-review/contracts/model-output.schema.json`

Source of Truth قرارداد Wire باقی بماند.

JSON Mode ساده یا Prompt-only JSON استفاده نشود.

کلید API را در کد، `appsettings`، مستندات یا Log قرار نده؛ فقط از User Secrets یا متغیر محیطی `ContentReview__ApiKey` خوانده شود. بدون کلید، برنامه باید اجرا شود و فقط درخواست بررسی پاسخ 503 بگیرد.

## محدودیت مرحله

Feature بعدی را شروع نکن.

Tool Calling، MCP، RAG، Qdrant و Agent وارد این Feature نشوند.

Package جدیدی غیر از `OpenAI 2.14.0` اضافه نکن، مگر اینکه `tasks.md` آن را مشخص کرده باشد؛ در غیر این صورت ابتدا گزارش بده.

Migration را روی پایگاه داده اعمال نکن.

`Prompts/` و `spec.md` را تغییر نده.

Constitution و تصمیم‌های تثبیت‌شدهٔ Technical Baseline را تغییر نده، مگر اینکه یک تعارض واقعی کشف شود؛ در آن صورت خودکار اصلاح نکن و فقط گزارش بده.

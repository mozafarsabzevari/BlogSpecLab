# راهنمای اعتبارسنجی: مدیریت و انتشار پست

| مشخصه | مقدار |
|-------|-------|
| قابلیت | `001-blog-post-management` |
| تاریخ | 2026-10-19 |
| طرح | [plan.md](./plan.md) |

> این راهنما پس از پیاده‌سازی معتبر می‌شود. در وضعیت فعلی Repository هنوز Solution و پروژه‌های C#
> ساخته نشده‌اند و دستورهای زیر هنوز قابل اجرا نیستند.

## پیش‌نیازها

- .NET 10 SDK
- (اختیاری) ابزاری برای ارسال درخواست HTTP، مانند `curl` یا فایل `.http` در محیط توسعه

## ساخت و آزمون

</div>

```powershell
dotnet build BlogSpecLab.slnx
dotnet test BlogSpecLab.slnx
```

<div dir="rtl">

**نتیجهٔ مورد انتظار:** ساخت بدون خطا انجام شود و همهٔ آزمون‌های Domain، Application و پذیرش HTTP
موفق باشند.

## اجرای برنامه

</div>

```powershell
dotnet ef database update --project src/02.Infra/DataAccess --startup-project src/03.Endpoints/Api
dotnet run --project src/03.Endpoints/Api
```

<div dir="rtl">

برنامه در محیط توسعه اجرا می‌شود و ورود آزمایشی با سرآیندهای `X-Dev-User-*` فعال است
([contracts/http-api.md](./contracts/http-api.md)).

## کاربران نمونه برای آزمون دستی

| کاربر | `X-Dev-User-Id` | `X-Dev-User-Roles` |
|-------|-----------------|--------------------|
| نویسندهٔ الف | `author-a` | `Author` |
| نویسندهٔ ب | `author-b` | `Author` |
| ویراستار ۱ (نویسنده هم هست) | `editor-1` | `Author,Editor` |
| ویراستار ۲ | `editor-2` | `Editor` |

## سناریوهای اعتبارسنجی

هر سناریو باید با یک آزمون پذیرش خودکار پوشش داده شود (اصل IV). جزئیات درخواست‌ها و کدهای خطا در
[contracts/http-api.md](./contracts/http-api.md) و قواعد وضعیت در [data-model.md](./data-model.md)
آمده است.

| ردیف | سناریو | نتیجهٔ مورد انتظار | مرجع |
|------|--------|-------------------|------|
| ۱ | نویسندهٔ الف پستی می‌سازد، ویرایش می‌کند و فهرست خود را می‌بیند | وضعیت «پیش‌نویس»؛ فقط پست‌های خودش در فهرست | US1، FR-002، FR-005 |
| ۲ | نویسندهٔ ب می‌خواهد پست نویسندهٔ الف را ببیند، ویرایش یا حذف کند | پاسخ 404 | US1، FR-004، SC-002 |
| ۳ | عنوان ۲۰۱ نویسه‌ای یا متن ۵۰٬۰۰۱ نویسه‌ای | پاسخ 400 با `InvalidTitle` یا `InvalidBody` | FR-002 |
| ۴ | نویسنده پست را ارسال می‌کند و سپس پس می‌گیرد | «در انتظار بررسی» و سپس «پیش‌نویس» | FR-006 |
| ۵ | ویراستار ۲ پست را با ذکر دلیل بازمی‌گرداند | «بازگشت برای اصلاح»؛ دلیل در فهرست نویسنده دیده می‌شود | US2، FR-005، SC-006 |
| ۶ | بازگرداندن بدون دلیل | پاسخ 400 با `ReturnReasonRequired` | FR-007 |
| ۷ | ویراستار ۱ پست خودش را تأیید می‌کند | پاسخ 403 با `SelfApprovalNotAllowed`؛ وضعیت «در انتظار بررسی» می‌ماند | FR-013، SC-002 |
| ۸ | ویراستار ۲ پست ویراستار ۱ را تأیید و ویراستار ۱ آن را منتشر می‌کند | «منتشرشده» | US3، FR-013 |
| ۹ | نویسنده‌ای بدون نقش ویراستار می‌خواهد تأیید یا منتشر کند | پاسخ 403 | FR-001، SC-002 |
| ۱۰ | انتشار پستی که «تأییدشده» نیست | پاسخ 409 با `InvalidStatusTransition` | FR-008، SC-002 |
| ۱۱ | خواننده بدون ورود فهرست را می‌بیند | فقط پست‌های منتشرشده، جدیدترین انتشار اول، با عنوان، نام نویسنده و تاریخ | FR-010، SC-003 |
| ۱۲ | خارج‌کردن از انتشار و انتشار دوباره بدون تأیید مجدد | «تأییدشده» و سپس «منتشرشده»؛ پست دوباره در فهرست عمومی دیده می‌شود | FR-009 |
| ۱۳ | نویسنده پست منتشرشده را بدون تأیید پیامد ویرایش می‌کند | پاسخ 409 با `ConfirmationRequired`؛ هیچ تغییری ذخیره نمی‌شود | FR-012 |
| ۱۴ | همان ویرایش با تأیید پیامد (`confirmRevertToDraft` برابر `true`) | «پیش‌نویس»؛ پست از فهرست عمومی حذف می‌شود | US3، FR-012 |
| ۱۵ | نویسنده پستی را که قبلاً منتشر شده و اکنون «پیش‌نویس» است حذف می‌کند | پاسخ 409 با `DeleteNotAllowed`؛ پست و سابقه‌اش باقی می‌مانند | US1، FR-003 |
| ۱۶ | دو ویراستار با یک شمارهٔ نسخه هم‌زمان تأیید و بازگرداندن را می‌فرستند | اولی موفق؛ دومی 409 با `ConcurrencyConflict` | FR-014 |
| ۱۷ | ویراستار پست تأییدشده را منتشر می‌کند و هم‌زمان نویسنده با تأیید پیامد آن را ویرایش می‌کند | با هر ترتیبی، وضعیت نهایی «پیش‌نویس» است و پست برای خوانندگان دیده نمی‌شود | FR-012 |
| ۱۸ | ویراستار سابقهٔ یک پست منتشرشده را می‌بیند | تأییدکننده و منتشرکننده همراه با زمان ثبت شده‌اند | FR-011، SC-001 |
| ۱۹ | ویراستار فهرست پست‌های «تأییدشده» و «منتشرشده» را می‌بیند | پست‌های همهٔ نویسندگان در همان وضعیت | US3، FR-015 |

## معیار تکمیل

- همهٔ سناریوهای جدول بالا در `dotnet test` به‌صورت خودکار موفق باشند.
- معیارهای SC-004 و SC-005 (زمان انجام کار توسط کاربر) با آزمون دستی سناریوهای ۱، ۴ و ۵ بررسی شوند.

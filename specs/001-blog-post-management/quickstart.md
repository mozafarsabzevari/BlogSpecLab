## ساخت کاربران نمونه و دریافت Token

پس از ساخت پایگاه داده، در محیط Development برای هر کاربر نمونه یک بار دستور زیر اجرا می‌شود
(research.md، R-20):

</div>

```powershell
dotnet run --project src/03.Endpoints/Api -- provision-user --name "Author A" --roles Author
dotnet run --project src/03.Endpoints/Api -- provision-user --name "Author B" --roles Author
dotnet run --project src/03.Endpoints/Api -- provision-user --name "Editor 1" --roles Author,Editor
dotnet run --project src/03.Endpoints/Api -- provision-user --name "Editor 2" --roles Editor
```

<div dir="rtl">

هر دستور شناسهٔ کاربر و Token او را فقط یک بار چاپ می‌کند. Token را در جای امن نگه دارید و در
Repository ثبت نکنید. برای Token جدید یک کاربر موجود از دستور `issue-token` استفاده می‌شود.

| کاربر نمونه | نقش‌ها |
|-------------|--------|
| نویسندهٔ الف (`Author A`) | نویسنده |
| نویسندهٔ ب (`Author B`) | نویسنده |
| ویراستار ۱ (`Editor 1`) | نویسنده و ویراستار |
| ویراستار ۲ (`Editor 2`) | ویراستار |

هر درخواست با سرآیند `Authorization: Bearer <token>` همان کاربر فرستاده می‌شود
([contracts/http-api.md](./contracts/http-api.md)). در آزمون‌های خودکار، کاربران و Tokenها مستقیماً
در پایگاه دادهٔ آزمون ساخته می‌شوند و به این دستور نیازی نیست.

## سناریوهای اعتبارسنجی

[contracts/http-api.md](./contracts/http-api.md) و قواعد وضعیت در [data-model.md](./data-model.md)
آمده است.

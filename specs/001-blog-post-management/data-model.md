# مدل داده: مدیریت و انتشار کنترل‌شدهٔ پست‌های وبلاگ

| مشخصه | مقدار |
|-------|-------|
| قابلیت | `001-blog-post-management` |
| تاریخ | 2026-10-19 |
| طرح | [plan.md](./plan.md) |

## موجودیت‌ها

### پست (`Post`)

ریشهٔ اصلی داده در پروژهٔ `Core.Domain`.

| فیلد | نوع | توضیح |
|------|-----|-------|
| `Id` | `Guid` | شناسهٔ پست (R-08) |
| `Title` | `string` | عنوان؛ الزامی، غیرخالی، حداکثر ۲۰۰ نویسه |
| `Body` | `string` | متن؛ الزامی، غیرخالی، حداکثر ۵۰٬۰۰۰ نویسه |
| `AuthorId` | `Guid` | شناسهٔ نویسنده (کاربر) |
| `AuthorDisplayName` | `string` | نام نویسنده در زمان ایجاد پست، خوانده‌شده از جدول کاربران (R-14) |
| `Status` | `PostStatus` | وضعیت فعلی |
| `CreatedAt` | `DateTimeOffset` | زمان ایجاد (UTC) |
| `LastModifiedAt` | `DateTimeOffset` | زمان آخرین تغییر محتوا یا وضعیت |
| `LastPublishedAt` | `DateTimeOffset?` | زمان آخرین انتشار؛ پس از خروج از انتشار پاک نمی‌شود (R-17) |
| `LastReturnReason` | `string?` | آخرین دلیل بازگشت (FR-005) |
| `Version` | `Guid` | نسخهٔ فعلی؛ با هر تغییر مقدار تازه می‌گیرد و به‌صورت `ETag` به Client داده می‌شود (R-11) |
| `StatusChanges` | فهرست `StatusChange` | سابقهٔ تغییر وضعیت |

ویژگی محاسبه‌شده: `HasEverBeenPublished` یعنی «آیا پست حداقل یک بار منتشر شده است» و وقتی درست است
که `LastPublishedAt` مقدار داشته باشد.

### وضعیت‌های پست (`PostStatus`)

| مقدار در کد | نام در Specification |
|-------------|----------------------|
| `Draft` | پیش‌نویس |
| `InReview` | در انتظار بررسی |
| `Returned` | بازگشت برای اصلاح |
| `Approved` | تأییدشده |
| `Published` | منتشرشده |

### سابقهٔ وضعیت (`StatusChange`)

هر رکورد، یک تغییر وضعیت پست را ثبت می‌کند.

| فیلد | نوع | توضیح |
|------|-----|-------|
| `Id` | `Guid` | شناسه |
| `PostId` | `Guid` | پست مربوط |
| `ActorId` | `Guid` | شناسهٔ کاربر انجام‌دهنده |
| `ActorDisplayName` | `string` | نام کاربر انجام‌دهنده (R-14) |
| `OccurredAt` | `DateTimeOffset` | زمان تغییر (UTC) |
| `FromStatus` | `PostStatus?` | وضعیت قبلی؛ هنگام ایجاد پست خالی است |
| `ToStatus` | `PostStatus` | وضعیت جدید |
| `Reason` | `string?` | دلیل؛ برای بازگشت الزامی است |

سابقه فقط افزوده می‌شود و هیچ رکوردی ویرایش یا حذف نمی‌شود، مگر همراه با حذف مجاز پستی که هرگز
منتشر نشده است (FR-003).

## کاربران، نقش‌ها و Tokenها

این داده‌ها فقط در `Infra.DataAccess` ذخیره می‌شوند و از طریق API ایجاد یا ویرایش نمی‌شوند؛ فقط
دستور راه‌اندازی محلی آن‌ها را می‌سازد (research.md، R-14 و R-20).

### کاربر (`User`)

| فیلد | نوع | توضیح |
|------|-----|-------|
| `Id` | `Guid` | شناسهٔ کاربر |
| `DisplayName` | `string` | نام نمایشی؛ الزامی |
| `IsActive` | `bool` | کاربر غیرفعال نمی‌تواند وارد شود |
| `CreatedAt` | `DateTimeOffset` | زمان ایجاد (UTC) |

### نقش کاربر (`UserRole`)

| فیلد | نوع | توضیح |
|------|-----|-------|
| `UserId` | `Guid` | کاربر |
| `Role` | `Role` | یکی از `Author` (نویسنده) یا `Editor` (ویراستار) |

کلید ترکیبی: کاربر و نقش. یک کاربر می‌تواند هر دو نقش را داشته باشد.

### Token دسترسی (`AccessToken`)

| فیلد | نوع | توضیح |
|------|-----|-------|
| `Id` | `Guid` | شناسه |
| `UserId` | `Guid` | کاربر صاحب Token |
| `TokenHash` | `string` | Hash نوع SHA-256 مقدار Token؛ یکتا. مقدار خام هرگز ذخیره نمی‌شود (R-19) |
| `CreatedAt` | `DateTimeOffset` | زمان صدور (UTC) |
| `ExpiresAt` | `DateTimeOffset?` | زمان انقضا؛ خالی یعنی بدون انقضا (R-18) |

Token وقتی معتبر است که Hash آن پیدا شود، منقضی نشده باشد و کاربرش فعال باشد.

## قراردادهای هویت و مجوز در `Core.Application`

این قراردادها در پایگاه داده ذخیره نمی‌شوند.

### کاربر فعلی (`ICurrentUser`)

فقط نتیجهٔ احراز هویت است و هیچ نقشی ندارد (R-06). پیاده‌سازی آن در `Endpoints.Api` است.

| فیلد | نوع | توضیح |
|------|-----|-------|
| `IsAuthenticated` | `bool` | آیا Token معتبر ارسال شده است |
| `UserId` | `Guid?` | شناسهٔ کاربر؛ برای کاربر واردنشده خالی |

### دسترسی فعلی کاربر (`IUserAccessReader`)

نقش‌ها و نام کاربر را هنگام هر عملیات حساس از پایگاه داده می‌خواند. پیاده‌سازی آن در
`Infra.DataAccess` است. خروجی آن `UserAccess` است:

| فیلد | نوع | توضیح |
|------|-----|-------|
| `UserId` | `Guid` | شناسهٔ کاربر |
| `DisplayName` | `string` | نام نمایشی |
| `IsActive` | `bool` | فعال بودن کاربر |
| `Roles` | مجموعهٔ `Role` | نقش‌های فعلی |

### خواندن Token (`IAccessTokenReader`)

AuthenticationHandler با این قرارداد، Token دریافتی را به شناسهٔ کاربر تبدیل می‌کند. پیاده‌سازی آن
در `Infra.DataAccess` است و Hash و بررسی انقضا و فعال بودن کاربر را انجام می‌دهد.

## روابط

- هر پست دقیقاً یک نویسنده دارد.
- هر پست صفر یا چند رکورد سابقهٔ وضعیت دارد. با حذف مجاز پست، سابقهٔ آن هم حذف می‌شود.
- هر کاربر صفر یا چند نقش و صفر یا چند Token دارد.

## انتقال‌های وضعیت

نمای کلی:

(Create)            ──► Draft
Draft               ──Submit──►    InReview
Returned            ──Submit──►    InReview
InReview            ──Withdraw──►  Draft
InReview            ──Approve──►   Approved
InReview            ──Return──►    Returned
Approved            ──Publish──►   Published
Published           ──Unpublish──► Approved
Approved/Published  ──Edit──►      Draft

| انتشار | تأییدشده | منتشرشده | هر ویراستار، از جمله نویسندهٔ پست | `If-Match` برابر نسخهٔ فعلی؛ زمان آخرین انتشار به‌روز می‌شود | FR-008، FR-013 |

## قواعد اعتبارسنجی

| قاعده | محل اجرا | کد خطا |
|-------|----------|--------|
| عنوان خالی یا بیش از ۲۰۰ نویسه | Domain | `InvalidTitle` |
| متن خالی یا بیش از ۵۰٬۰۰۰ نویسه | Domain | `InvalidBody` |
| دلیل بازگشت خالی | Domain | `ReturnReasonRequired` |
| انتقال غیرمجاز | Domain | `InvalidStatusTransition` |
| تأیید پست توسط نویسندهٔ خودش | Domain | `SelfApprovalNotAllowed` |
| حذف پستی که قبلاً منتشر شده است | Domain | `DeleteNotAllowed` |
| ویرایش پست تأییدشده یا منتشرشده بدون تأیید نویسنده | Application | `ConfirmationRequired` |
| سرآیند `If-Match` در فرمان تغییر وضعیت ارسال نشده | Api | `PreconditionRequired` |
| قالب سرآیند `If-Match` نامعتبر | Api | `InvalidIfMatch` |
| نسخهٔ `If-Match` قدیمی، یا تغییر هم‌زمان هنگام ذخیره | Application | `StaleVersion` |
| Token غایب، نامعتبر، منقضی یا متعلق به کاربر غیرفعال | Api (احراز هویت) | `Unauthenticated` |
| نقش ناکافی براساس نقش‌های ذخیره‌شده در سرور | Application | `Forbidden` |
| پست دیگران یا پست غیرقابل مشاهده | Application | `NotFound` |

## چه کسی چه پست‌هایی را می‌بیند

| کاربر | پست‌های قابل مشاهده |
|-------|---------------------|
| خواننده (حتی بدون ورود) | فقط پست‌های منتشرشده |
| نویسنده | همهٔ پست‌های خودش در هر وضعیت، به‌علاوهٔ پست‌های منتشرشدهٔ دیگران از مسیر عمومی |
| ویراستار | پست‌های همهٔ نویسندگان در وضعیت‌های در انتظار بررسی، تأییدشده و منتشرشده، همراه با سابقهٔ آن‌ها (FR-011، FR-015)؛ برای پست‌های پیش‌نویس و بازگشت برای اصلاح فقط سابقهٔ وضعیت، بدون عنوان و متن (FR-011) |

## نکات ذخیره‌سازی

- جدول‌ها: `Posts` برای پست‌ها، `PostStatusChanges` برای سابقهٔ وضعیت، `Users` برای کاربران،
  `UserRoles` برای نقش‌ها و `AccessTokens` برای Tokenها.
- Index یکتا روی `AccessTokens(TokenHash)`.
- نمایه (Index) روی وضعیت و زمان آخرین انتشار برای فهرست خوانندگان و ویراستار، و روی شناسهٔ نویسنده
  برای فهرست نویسنده.
- وضعیت پست به‌صورت متن ذخیره می‌شود تا داده خوانا بماند.
- فیلد `Version` به‌عنوان Concurrency Token در EF Core تنظیم می‌شود.
